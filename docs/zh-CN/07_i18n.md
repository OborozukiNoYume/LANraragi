# 国际化（i18n）

> 基准 commit `2094cc1d`（2026-09-04）。事实已对照代码核实——生成时已逐条核查引用。

## 概述

LANraragi 使用单一消息目录在两个层面对其 Web UI 进行翻译：

- **后端 / 模板** —— Template Toolkit 文件调用 `c.lh()` 助手，该助手通过从 `locales/template/` 中的 Gettext `.po` 文件加载的 `Locale::Maketext` 词法表来解析消息。
- **前端 / JavaScript** —— **不存在静态的 `public/js/i18n.js` 文件**。服务器会将 `templates/i18n.html.tt2` 即时渲染为 JavaScript，因此浏览器端代码无需任何客户端 i18n 库即可获得相同的已翻译字符串。

面向用户的工作流（Weblate、`.po` 编辑规则）在上游文档 `tools/Documentation/extending-lanraragi/translations.md` 中说明。

### 关键文件

| 文件 | 作用 |
|---|---|
| `lib/LANraragi/Utils/I18N.pm` | Maketext 子类；声明词法表（句柄 → `.po` 映射） |
| `lib/LANraragi/Utils/I18NInitializer.pm` | 注册 `lh` 助手；语言协商与回退 |
| `lib/LANraragi.pm` | 在应用启动时调用初始化器 |
| `lib/LANraragi/Controller/I18N.pm` | 将前端字符串模块渲染为 JavaScript |
| `lib/LANraragi/Utils/Routing.pm` | 暴露 `GET /js/i18n.js` 路由 |
| `templates/i18n.html.tt2` | `I18N` JavaScript 对象的服务器端来源 |
| `templates/common/importmap.html.tt2` | 将 `i18n` 模块说明符映射到 `/js/i18n.js` |
| `templates/templates_config/config_global.html.tt2` | 设置页中的语言下拉框 |
| `locales/template/*.po` | Gettext 消息目录（14 个文件，12 个可加载） |
| `tools/Documentation/extending-lanraragi/translations.md` | 上游贡献者指南 |

## 后端：Maketext 词法表

`lib/LANraragi/Utils/I18N.pm` 继承自 `Locale::Maketext`，并通过 `Locale::Maketext::Lexicon` 使用 `Gettext` 格式为每种语言声明一个词法表：

```perl
use Locale::Maketext::Lexicon {
    de      => [ Gettext => "../../locales/template/de.po" ],
    en      => [ Gettext => "../../locales/template/en.po" ],
    ...
    _auto   => 0,
};
```

- `.po` 路径相对于该模块在磁盘上的位置，指向 `locales/template/`。
- `_auto => 0` 关闭了 Auto 词法回退：缺失的查找会抛出错误而不是静默返回键本身——这正是 `lh` 助手用 `eval` 加 `en` 重试所捕获的情形（见下文）。语言选择完全由 LANraragi 自身的逻辑完成，因为 `get_handle` 总是拿到一份显式候选列表；`Locale::Maketext` 从不查询语言环境相关的环境变量。
- 两个模块都在 `tools/cpanfile` 中固定了版本：`Locale::Maketext` 1.33 和 `Locale::Maketext::Lexicon` 1.00。

### 已注册的语言

`lib/LANraragi/Utils/I18N.pm` 中的词法表注册了 14 个句柄键，映射到 12 个不同的 `.po` 文件（地区别名共享同一文件）：

| 句柄 | `.po` 文件 | 语言 |
|---|---|---|
| `de` | `locales/template/de.po` | 德语 |
| `en` | `locales/template/en.po` | 英语 |
| `es` | `locales/template/es.po` | 西班牙语 |
| `fr` | `locales/template/fr.po` | 法语 |
| `id` | `locales/template/id.po` | 印度尼西亚语 |
| `ja` | `locales/template/ja.po` | 日语 |
| `ko` | `locales/template/ko.po` | 韩语 |
| `pt` | `locales/template/pt.po` | 葡萄牙语 |
| `vi` | `locales/template/vi.po` | 越南语 |
| `zh`, `zh-cn` | `locales/template/zh.po` | 中文（简体） |
| `no`, `nb` | `locales/template/nb_NO.po` | 书面挪威语（Bokmål） |
| `zh-tw` | `locales/template/zh_Hant.po` | 中文（繁体） |

别名键的存在使浏览器发送的地区标签能够解析到某个词法表；实际翻译由别名目标承载。

### 未注册的 `.po` 文件：意大利语和阿萨姆语

`locales/template/` 包含 14 个 `.po` 文件，但只有 12 个可被访问：

- `locales/template/it.po`（意大利语）和 `locales/template/as.po`（阿萨姆语）**未在** `lib/LANraragi/Utils/I18N.pm` 中**注册**，因此没有任何语言句柄能加载它们，其翻译也永远不会到达 UI。
- `templates/templates_config/config_global.html.tt2` 中的语言下拉框仍然提供 `it`（Italiano）选项。选中它会让 `get_handle` 跳过这个未知标签并落到英语回退上——尽管代码树中存在 `it.po`，UI 仍保持英语。
- `as` 则完全不在下拉框中提供。

简而言之：**实际可加载的语言为 12 种**，意大利语正是 UI 选项列表与已注册词法表之间唯一的缺口。

## 语言协商

`lib/LANraragi/Utils/I18NInitializer.pm` 在 Mojolicious 应用上注册了 `lh` 助手；它在 `lib/LANraragi.pm` 启动期间被接入（`LANraragi::Utils::I18NInitializer::initialize($self)`）。助手内部的解析顺序：

1. **强制语言** —— 服务器级语言设置在启动时通过 `$app->LRR_CONF->get_language` 读取一次，并存储为应用的 `forced_language` 默认值（避免每个请求都查询 Redis）。如果它已设置且不为 `auto`，则优先采用。
2. **`Accept-Language` 头** —— 当设置为 `auto` 时，请求的 `Accept-Language` 按逗号拆分并去掉权重值（`;q=0.8`），以保留浏览器的偏好顺序。
3. **英语回退** —— 若候选列表中没有 `en`，则将其追加进去。

候选列表会传给 `LANraragi::Utils::I18N->get_handle(@langs)`，它返回第一个可加载的句柄（这正是 `it` 这类不受支持的标签退化为英语的原因）。`maketext` 被包在 `eval` 中：出错时会用 `en` 句柄重试该消息，若仍然失败则返回原始消息键。参数在翻译前被编码为 UTF-8，结果再被解码回来。

强制语言设置保存在 Redis 配置中（默认 `auto`，见 `lib/LANraragi/Model/Config.pm` 中的 `get_language`），从 `templates/templates_config/config_global.html.tt2` 的下拉框中选取；该模板注明它需重启后才能完全生效——与启动时读取一次的设计一致。

### 请求流程一览

对于单条已翻译字符串，端到端流程如下：

1. 模板调用 `c.lh("Add Archives")`；助手检查 `forced_language` stash 默认值（启动时设置）。
2. 若为 `auto`，请求的 `Accept-Language`（例如 `zh-TW,zh;q=0.8,en;q=0.3`）会被解析为 `zh-TW`、`zh`、`en`。
3. 若缺少 `en` 则追加之，然后 `LANraragi::Utils::I18N->get_handle(@langs)` 选中第一个拥有已注册词法表的语言（本例中 `zh-tw` → `zh_Hant.po`）。
4. `$handle->maketext("Add Archives")` 执行查找，参数事先编码为 UTF-8，结果事后解码。
5. 任何查找错误都会被捕获，改用 `en` 句柄重试，最终仍失败则返回原始键。

## 前端：服务器生成的 JavaScript 模块

- `lib/LANraragi/Utils/Routing.pm` 暴露了 `GET /js/i18n.js`（位于公开路由集上，这意味着启用 No-Fun Mode 时它同样处于登录保护之后），分发到 `i18_n#index`。
- `lib/LANraragi/Controller/I18N.pm` 以 `Content-Type: application/javascript` 渲染 `i18n` 模板。
- `templates/i18n.html.tt2` 通过为每个条目插值 `c.lh()` 来构建 `const I18N = {...}` 对象——撰写本文时共有 255 处插值。条目有两种形态：

```javascript
I18N.SaveSuccess = "[% c.lh("Saved!") %]";
I18N.BatchSleeping = (x) => `[% c.lh("Sleeping for \${x} seconds.") %]`;
```

  静态字符串使用普通常量，接受运行时参数的字符串使用箭头函数（占位符在浏览器中通过模板字面量填充）。

- `templates/common/importmap.html.tt2` 将裸模块说明符 `i18n` 映射到 `/js/i18n.js?$version`（版本查询参数用于跨版本刷新缓存）。`public/js/` 下有 19 个模块通过 `import I18N from "i18n"` 使用它。

由于该文件按请求渲染，浏览器端字符串始终遵循与服务器渲染页面相同的强制语言/Accept-Language 协商。

## 模板中的用法

将用户可见的文本包在 `c.lh()` 中（`templates/` 下有 20 个模板在使用它）：

```html
<a href="[% c.url_for("/upload") %]">[% c.lh("Add Archives") %]</a>
```

模板中的占位符使用 Maketext 方括号记法并以后置参数传递：

```html
[% c.lh("Version [_1] [_2]", version, vername) %]
```

## 翻译目录

- `locales/template/en.po` 是源目录文件：包含 639 个消息条目（含空头部在内共 640 行 `msgid`），划分为 20 个区段、每个模板一个（包括存放前端字符串的 `i18n.html.tt2`）。其中 19 个区段由 `# ------Start of ...------` 注释界定；i18n 区段的开头界定符在目录中被误拼为 `# ------Stary of i18n.html.tt2------`，因此用 `Start of` 来 grep 只会找到 19 个。还有两个条目（`Rescan Archive Directory` 及其帮助文本）位于 Upload 与 i18n 区段之间，不在任何界定符之内。
- 每种语言保持相同的 `msgid` 键；只有 `msgstr` 值不同。

`locales/template/en.po` 的一个典型片段：

```
# ------Start of Backup.html.tt2------
msgid "Database Backup/Restore"
msgstr "Database Backup/Restore"

msgid "Restoring your backup ..."
msgstr "Restoring your backup ..."
# ------End of Backup.html.tt2------
```

在英语文件中 `msgid` 与 `msgstr` *通常*相同——例外包括 JS 占位符条目（`msgstr` 去掉 `\$`
转义）以及少数 `msgstr` 添加了标记或空白的条目（如 `Version %1 %2` 变为 `Version %1 - %2`）。
其他语言则各不相同，但键必须与模板传给 `c.lh()` 的内容逐字节一致。

## 翻译工作流

翻译托管在 Weblate 上（`README.md` 中有徽章，贡献者指南见 `tools/Documentation/extending-lanraragi/translations.md`）：在 `https://hosted.weblate.org/projects/lanraragi/lanraragi-source/` 提交的翻译会以拉取请求的形式回提交到 GitHub 仓库。

若要直接在代码树内翻译：

1. 将 `locales/template/en.po` 复制为 `locales/template/` 中的新文件 `<lang>.po`，翻译 `msgstr` 值，保持 `msgid` 不变。
2. 遵守占位符约定，不同层面的约定有所差异：
   - HTML 模板：模板中的 `[_1]` 对应 `.po` 条目中的 `%1`。
   - JavaScript：`i18n.html.tt2` 与 `.po` 文件中的 `msgid` 对美元符转义（`\${title}`），而 `msgstr` 使用字面量 `${title}`。
3. 保持已翻译字符串内的 HTML 标记（`<br/>`、`<b>`、链接）完好。
4. **精确**匹配 `msgid` —— `c.lh()` 调用中一个多余的尾部空格都会导致条目无法匹配任何目录键。
5. 注意 `~` 的怪癖：`~` 在 `Locale::Maketext` 中是转义字符，因此包含 `~` 的 `msgid` 将无法匹配；让 `~` 远离 `msgid`，只出现在 `msgstr` 中（`config_tags` 中的标签语法帮助字符串就是这样处理的）。

新增一个字符串需要改动三处：模板（JS 则是 `templates/i18n.html.tt2`）、`locales/template/en.po` 中一对匹配的 `msgid`/`msgstr`，最终还有其他 `.po` 文件。

## 新增一种语言

1. 从 `en.po` 创建 `locales/template/<lang>.po`。
2. 在 `lib/LANraragi/Utils/I18N.pm` 中注册一个指向新文件的句柄——**不做这一步，该文件就是死重**（即当前 `it.po`/`as.po` 的处境）。
3. 在 `templates/templates_config/config_global.html.tt2` 的语言 `<select>` 中添加一个 `<option>`。
4. 重启服务器，以刷新启动时设定的强制语言默认值。

## 怪癖与故障排查

- **某字符串明明已翻译却仍显示英语。** `msgid` 匹配是精确匹配；`c.lh()` 中一个尾部空格或不同的引号方式都会破坏查找，未知键在经过 `lib/LANraragi/Utils/I18NInitializer.pm` 中的双重回退后会按原键本身渲染。
- **选择意大利语却得到英语。** 下拉框提供 `it`，但并未注册对应句柄（见上文）；`get_handle` 会跳过它并落到追加的 `en` 上。
- **强制语言似乎过期了。** 它在启动时被一次性读入 `forced_language` 默认值；修改 Redis 配置后只有重启才会生效。
- **语言环境相关的环境变量被忽略。** `lib/LANraragi/Utils/I18NInitializer.pm` 中的 `get_handle` 总是拿到一份显式候选列表（强制设置，随后 `Accept-Language`，最后 `en`），因此 `Locale::Maketext` 从不自行做环境检测；只有这些候选起作用。
- **前端字符串与页面其余部分表现不一致。** 它们来自同一次 `/js/i18n.js` 渲染，但浏览器会缓存 JavaScript——importmap 中的 `?$version` 缓存清除参数正是为了在升级时让该缓存失效。
- **未知操作的日志行会直接崩溃。** `templates/i18n.html.tt2` 中的 `BatchUnknownOperat` 箭头函数插值了 `${oper}`，但其 `(id, msg)` 参数列表从未定义该变量——调用它（当服务器回答 "Unknown operation type" 时 `batch.js` 会这样做）会抛出 `ReferenceError` 而非渲染消息。仅为潜在问题：原版 UI 只发送服务器认识的五种操作。
